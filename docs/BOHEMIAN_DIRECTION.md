# 波西米亚导播 v1

主线 `/studio/band/` 载入波西米亚示例后启用「作品导播」；「导播镜头」可以跳到任意镜头。「观看模式」隐藏控制面板。拖动、滚轮、固定机位或双击乐器会交还手动控制，重新勾选作品导播从当前歌曲时间恢复。

本版是针对这份 MIDI、灯光和七幕 LED 内容编排的 27 个镜头。灯光/LED 的重要换段前回到全景，叙事段和尾声再给演奏特写；歌剧与摇滚主体留给舞台。特写声部已对照实际音符检查，尾声不用已经停奏的吉他。

乐器镜头覆盖全部七个实例：钢琴 3 段、电子琴 3 段、架子鼓 2 段、贝斯 1 段、萨克斯 2 段、两把电吉他分别 2 / 1 段。电子琴展示双层键盘的合声与弦乐，架子鼓在叙事和摇滚段分别使用肩后与高位俯拍；换幕窗口仍保留全景。

片头片尾是独立文字轨：`src/shows/BohemianTitles.ts` 编排歌名、QUEEN 和「yezhen 制作」。片头在 2–13.5 秒下方出现，片尾在拍 466 后 1.5 秒居中出现，最后与舞台一起渐黑，留 0.8 秒黑场。导演面板提供「片头片尾」开关及两个预览按钮，手动换镜头不改变文字时间。

`src/titles/TitleShow.ts` 按歌曲绝对时间计算淡入淡出；`TitleLayer.ts` 用 Canvas 排字，作为独立正交图层合成在场馆后期之后、同一 WebGL 画布上。它不受舞台灯光与 Bloom 影响，不依赖 DOM 叠字，未来离线导出也须调用这一步合成。未匹配的 MIDI 或布局模式清除文字轨。验证入口：`node scripts/verify-titles-browser.mjs`（Chrome，沿用 `PLAYWRIGHT_MODULE` 设置）。

## 编排与执行

- `src/shows/BohemianCamera.ts`：乐曲镜头数据。以四分音符拍号定位，通过真实速度图转换成秒；构图允许新增，不依赖自由弹奏的固定机位。
- `src/shows/CameraShow.ts`：镜头数据契约。每个 cue 含时间、名称、起止构图；默认直接切镜头，原作品使用构图插值和可选短距离 glide。开放接口也支持明确位置、自定义运动与转场路径，见 [演出创作接口](SHOW_AUTHORING.md)。单个 cue 固定主体。
- `src/camera/CameraShowPlayer.ts`：按绝对歌曲时间计算相机；不播放音频、不更新灯光或屏幕。主体通过类型和实例序号绑定实际 ID；缺失主体或轨迹求值错误保留上一有效机位并报告错误。舞台镜头使用场景坐标，乐器镜头使用模型本地坐标，经过已有相机层转换。
- `src/shows/catalog.ts`：把相同歌曲的镜头、灯光和 LED 编排一起准备；三者读取同一播放器时间。场景加载、镜头控制权仍由宿主和 StageDirector 负责。

## 后续编排约束

1. 修改整场作品时同时检查 LED 幕切换和灯光换段，不能只看 MIDI 音符密度。当前重点边界为拍 20、64、100、186、222、252、296、378、410、466。
2. `subject.instance` 是同类乐器的零基序号；两把电吉他必须分别指定，不用类型名代替实例。
3. 跨乐器、跨舞台的大距离变化用切镜头。`glide` 仅用于相邻全景的小幅重构图，避免穿越乐器和掠过舞台。
4. 当前起始 cue 为 0，按时间递增，最后一个镜头保持至歌曲结束。运动直接取决于歌曲时间，暂停冻结、seek 直接复原；减少动态效果偏好下使用静态构图。
5. 运行 `npm run camera:performance:verify` 校验实际 MIDI 分配：每段特写切入时须有本实例正在持续的音符，镜头内连续休止不得超过 1 秒（合并上下层及多声部，包含末尾休止）。这是编排校验，不是逐帧自动切镜头；正常短休止继续保留。拍 160–170 用舞台中景承接，拍 170（130.769 秒）才切电子琴。
6. 下一轮以实际观看反馈调整停留和构图。本版没有增加任意歌曲的自动导播生成器，也没有更改原 MIDI 音频。

验证：`npm run typecheck`；设置 `PLAYWRIGHT_MODULE` 后运行 `node scripts/verify-camera-show-browser.mjs`。覆盖 27 个镜头的起点/中点、全部七个乐器实例的特写覆盖、视域边界、往返 seek、运动、暂停、手动接管和恢复，另检查电子琴和架子鼓新增构图。
