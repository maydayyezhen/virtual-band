# 乐队舞台主线：独立场馆与布局

2026-09-11。主线 `/studio/band/`。已完成独立场馆、实例布局和自动排位；后续按用户确认接入独立歌曲灯光架构及波西米亚示例，见 [LIGHTING_SYSTEM.md](LIGHTING_SYSTEM.md)。LED 通用内容源和参考的波西米亚七幕三屏剧场已接入，见 [SCREEN_CONTENT.md](SCREEN_CONTENT.md)；自动镜头仍未接入。

## 已实现的分工

| 模块 | 责任 |
| --- | --- |
| `venues/nocturne/NocturneVenue` | 独立场馆根节点、场景配置、渲染附件、update/dispose；不管理乐器或镜头 |
| `NocturneAsset.js` | 保留原有几何、材质、装饰照明、LED 图案、雾与泛光；静态模块导入，实例独立状态 |
| `NocturneSpec` / `StageLayout` | 舞台高度、可摆放区域、禁区与间距；镜头活动区域单独定义 |
| `BandPresentation` | 把模型统一成米，居中 X/Z 并落地；模型归一化和实例变换分为内外两个节点 |
| `LayoutDocument` | 按实例 ID 保存类型、位置、水平朝向、比例和锁定状态 |
| `AutoLayout` | 纯数据计算；实测尺寸与演奏占地取大值，考虑旋转、间距、边界、禁区、锁定和已有位置 |
| `BandSession` | 准备并验证新布局，精确应用保存的布局，支持重新排列；不播放声音 |
| 主页面 `mountBand` | 首次装配、MIDI 换曲和 JSON 布局共用的提交入口；集中更新实例注册、近景模式、视图和场景 |

旧 `NocturneLayoutStage.ts` 和编辑器中的七份压缩源码副本已移除。主线不再通过解压、字符串替换、临时 window 全局或 `Function()` 加载场馆。独立的旧灯光试验页暂未迁移，也没有接入主线。

场馆资产保留为普通 JavaScript，外层提供 TypeScript 类型边界；没有为了改架构重做材质和几何。场馆更新由主页面/编辑器现有循环传入 dt，渲染只负责输出。每个实例各自拥有随机种子、雾、灯具和屏幕状态。

## 数据流

```text
场馆约束 + 乐器实例/尺寸 + 已有布局/锁定
                   ↓
             AutoLayout 计算
                   ↓
          BandSession 验证并准备
                   ↓
             mountBand 提交
                   ↓
实例 ID → holder 的绝对变换 → 镜头重新取景
```

摆放层不再按“同类型第几个”匹配，也不再截断越界坐标或累乘比例。重复应用同一布局不会继续放大、下沉或换位。模型仅归一化一次，演奏动作不影响布局尺寸的基准。

新增已有类型的乐器只需 `{ id, type }`，再由已有目录创建实例。布局算法没有每件乐器的专用代码分支；单个鼓组默认偏好舞台中线。新增类型仍需要实现模型、音频适配和交互，并在定义中提供真实尺寸、演奏占地与站位偏好。

## 自动排列与失败处理

- `Formation.ts` 先根据整个编制生成队形：后排中心、左右侧翼、前排浅弧。站位偏好来自乐器定义中的 `placement`，核心不判断乐器类型名称。
- 换曲和“重新排位”都重排未锁定的位置；模型对象、ID、比例和朝向继续复用。只有显式锁定的位置保持不动，避免新乐器围着历史位置不断补位。
- 占位由模型矩形与演奏空间共同决定，并计入 Y 轴旋转。
- 主线和编辑器显式传入 `venue.layout`。NOCTURNE 提供 X −12…12 m、Z −5.4…6.6 m、舞台高 1.2 m；编队核心不导入 NOCTURNE，也不认识镜头或场景对象。
- 首选位置冲突时，优先保持前后层次，在有界网格上寻找替代位置；通常步长不超过 0.25 m，每轴最多 97 个采样点，大场馆自动降低采样密度。
- 返回 `layout / unplaced / issues`；应用入口遇到问题会保留当前布局并显示原因，不隐式缩小模型。

这是确定性的实用排布，不是保证找到最优解的几何求解器。保守矩形占位可能拒绝某些实际能嵌套摆放的形状；排布失败不等于数学上证明无解。内部道具不参与人物物理碰撞。

场馆的 `gap` 是最小避让间距；`CONCERT_FORMATION` 的行距、前排展开宽度和弧度属于编队构图。`AutoLayout.ts` 只把布局文档、实测尺寸和乐器描述转换为核心输入。`validateLayout` 独立校验保存的位置，不通过执行一遍自动编队来验证。具体接口见 [FORMATION.md](FORMATION.md)。

## 页面行为与兼容

主舞台“重新排位”重新计算当前编制，保留锁定位置、比例和朝向。拖入 MIDI 时复用相同 ID 的乐器对象；新增实例先准备好，布局验证失败不替换原场景。编辑器导出的 JSON 可拖入主舞台，按保存的 ID 和变换精确加载，停止歌曲并进入自由弹奏。布局越界或冲突时给出错误，不悄悄改写坐标。

编辑器的锁定状态进入布局文档，支持保存/加载和撤销。旧 schema-3 `atelier-studio` 布局仍能读取：原先隐藏的 1.5 倍显示比例转换为显式实例 scale，保存后不会重复转换。新建布局默认按真实米制尺寸显示。旧布局若本来已经重叠，仍需在编辑器中重新排位后再加载主舞台。

MIDI 模型和布局准备失败会释放新建实例，已有实例保持可用。歌曲解析/合成器加载自身的失败由播放器报错；本阶段不宣称完整的音频事务回滚。

## 验证

- `npm run layout:verify`：序列化、旧文档迁移、ID、不同尺寸、旋转、边界、间距、禁区、锁定、编制重排、队形构图与容量不足。
- `npm run formation:browser`：Chrome 验证七件编制的宽深、真实尺寸、对象复用、重新排位幂等、不同历史布局后载入同一歌曲、锁定位置保留；可设置 `SCREENSHOT_DIR` 保存正面、俯视和全景。
- `npm run stage:browser`：Chrome 验证场馆几何保留、独立实例和销毁、真实尺寸/落地、幂等应用、换曲复用、JSON 对应关系、锁定及失败保留原场景。
- `npm run camera:browser`：固定视角、近景、自由移动、触屏与镜头切换。
- `npm run live:browser` 与 `node scripts/verify-band-browser.mjs`：独立弹奏、重复乐器、MIDI 播放/暂停/换曲、布局编辑器。
- `npm run build`：类型检查与生产构建。

提取前后场馆均为 614 个 Mesh、39 盏 Light、526740 个展开实例后的顶点；同一时刻/机位截图对比保留了原有场馆外观。

## 后续边界

场馆原有装饰灯光保留为默认状态。匹配歌曲编排时，由 `LightingSession` 读取现有播放器时间并独占灯光控制，关闭后恢复装饰状态；屏幕与镜头仍保持各自控制权。没有接入旧演出导演或第二套音频时钟。
