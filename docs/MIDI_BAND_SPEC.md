# MIDI 驱动虚拟乐队 · 规格

> 2026-09-11 更新：本文的乐器分配规则现在只影响画面。原始 MIDI 由 SpessaSynth 完整播放，不过滤短轨、不按模型音域删音、不截短长音。下文历史实现描述若涉及自研音频调度，以 [MIDI_PLAYBACK.md](MIDI_PLAYBACK.md) 为准。


**目标**：任意一个 MIDI 文件丢进来，自动分配出一支虚拟乐队，让它们按谱演奏。

**原则**：尽可能符合现实——现实中一个岗位一个人，缺的声部由键盘手补。

**状态**：规格已定，**MIDI 驱动已实现并跑通端到端**（见第 10 节）。

各乐器的**音色接入已经做完**（见 7.1），剩余的"调音色"工作见第 8 节。第 4 节的键盘部分已实现并验证。

---

## 1. 总流程

```
任意 MIDI
   │
   ├─ ① 逐条轨：取解析器提供的 program + 通道
   │
   ├─ ② 按归并表 → 已注册的乐器类型
   │
   ├─ ③ 每一类算"同一时刻最多几个声部" → 定件数
   │
   ├─ ④ 自动排布到舞台
   │
   └─ ⑤ 播放：按时间把音符推给对应乐器的对应层
```

**没有按曲子的特殊处理。** 同一套规则吃所有 MIDI。

## 2. 归并表

本节与代码统一使用 **0–127 的 GM program 编号**。部分音色手册显示 1–128，转换到代码时必须减 1；通道在代码中同样从 0 开始，第 10 通道是 `channel === 9`。
标准名称参照 [Standard MIDI Patch Assignments](https://learn.microsoft.com/en-us/windows/win32/multimedia/standard-midi-patch-assignments)。

本表只决定舞台上用哪个模型表现音轨；原始 MIDI 的音色、控制器和音符继续由 SpessaSynth 播放。键盘是暂缺模型的显示后备，分配到键盘不会把原音频改成钢琴。

| Program（0 起） | 音色 | 显示模型 |
|---|---|---|
| 0–1、3 | 原声三角钢琴、明亮钢琴、酒吧钢琴 | 三角钢琴（88 键） |
| 2、4–23 | 电声三角钢琴、电钢琴、色彩打击、风琴 | 双层键盘 |
| 24–25 | 尼龙弦、钢弦木吉他 | 木吉他 |
| 26–31 | 电吉他及吉他泛音 | 电吉他 |
| 32–37 | 原声贝斯、电贝斯、击弦贝斯 | 贝斯 |
| 38–39 | 合成贝斯 | 键盘 |
| 40–41、43 | 小提琴、中提琴、低音提琴 | 提琴模型，按音色调整定弦 |
| 42 | 大提琴 | 独立大提琴与琴弓模型 |
| 44 | Tremolo Strings 震音弦乐 | 键盘，暂无专用震音表现 |
| 45 | Pizzicato Strings 拨弦弦乐 | 提琴，使用已有拨弦动作 |
| 46 | Orchestral Harp 竖琴 | 键盘，暂无竖琴模型 |
| 47 | Timpani 定音鼓 | 键盘，暂无定音鼓模型 |
| 48–55 | 弦乐合奏、合唱、管弦乐重击 | 键盘 |
| 56–63 | 铜管 | 键盘 |
| 64、66–71 | 其他萨克斯、双簧管、英国管、巴松、单簧管 | 键盘 |
| 65 | 中音萨克斯 | 中音萨克斯模型 |
| 72–79 | 笛管类 | 键盘 |
| 80–103 | 合成主音、铺底、效果 | 键盘 |
| 104–111 | 民族乐器 | 键盘 |
| 112–119 | 旋律通道的打击乐 | 键盘 |
| 120–127 | 音效 | 键盘 |
| 第 10 通道（代码 9） | 打击乐 | 鼓组，优先于 program |

GM 的 strings 家族包含弓弦、拨弦和定音鼓，所以模型路由不能只看家族名称。特别注意：46 是竖琴，47 是定音鼓，48 已进入弦乐合奏；128 不是有效的 GM program。

解析器提供每条轨的代表 program，当前路由直接使用它，没有统计逐音符音色出现次数。原始 Program Change 仍由音频播放器处理。无效的旋律 program 使用键盘后备并给出原因，不进入正常编号区间。

### 2.1 扩展与验证

新增实体乐器时再替换相应的模型路由；音频引擎不依赖此表。提琴的 MIDI 视觉入口接到 45 时切拨弦，接到弓弦音色时切回运弓，避免复用模型后残留上一次技法。

大提琴接入仅替换独奏音色 42；48/49 弦乐合奏继续由键盘显示，不把整支弦乐组伪装成一位大提琴手。

`npm run midi:routing:verify` 覆盖全部 128 个编号、关键边界名称、鼓通道优先级、异常编号、真实 MIDI 编解码和波西米亚音轨。`GeneralMidiTones.ts` 的音色名数组原本已按 0 起编号排列，本次修正的是路由边界和旧说明。

## 3. 件数规则

| 乐器 | 件数 | 理由 |
|---|---|---|
| **鼓** | **恒 1** | 一套鼓天生多声部（底鼓/军鼓/嗵鼓/镲同时响很正常），不存在"演不出来"；现实中不会两个鼓手共用一套鼓。多条鼓轨并到一套上 |
| **贝斯** | **恒 1** | 合成贝斯（39–40）已分给键盘，剩下归贝斯的都是真实贝斯音色，现实中就是 1 把 |
| **键盘** | **有声部时恒 1** | MIDI 后备声部集中到一台双层键盘，同层允许多声部叠加 |
| **电吉他 / 木吉他 / 提琴** | **算** | 按"同一时刻最多几条轨在响" |

### 3.1 "同一时刻最多多少"怎么算

```
① 归类完成后，把该类的所有轨的音符合并
② 每个音符产生两个事件：开始(+1)、结束(−1)
③ 按时间排序，扫一遍
④ 记录"此刻有几条轨正在响"的峰值
⑤ 只看持续 > 1 秒的重叠（短于一秒的叠音听不出来，不算）
```

判定：

| 同时声部 | 持续时长 | 结果 |
|---|---|---|
| ≤ 2 | — | **1 件** |
| 3–4 | < 1 秒 | **1 件**（挤一下，次要的略过） |
| 3–4 | > 1 秒 | **2 件** |
| 5+ | > 1 秒 | 继续加 |

**键盘不按同时声部数扩容**：先将超出上层 36–96 音域的轨分给下层，其余轨按时间重叠较少、已分配轨数较少的顺序选择上下层。多条轨可同时按亮同一层；同音高重叠由视觉时间线合并释放。原始 MIDI 的音色与音符仍由独立播放器完整播放。

当前《波西米亚》7 个后备声部合并到 1 台键盘，整支乐队由 9 件变成 7 件。其余乐器的件数规则不变。

### 3.2 一件乐器自身能演几个音

超出时不是立刻加件，**先让这件乐器自己吸收**（它天生多声部）：

| 乐器 | 同时最多 |
|---|---|
| 键盘 | 10（十指，常用 6–8） |
| 电吉他 / 木吉他 | 6（六根弦） |
| 贝斯 / 提琴 | 4（四弦） |

接不下的音由乐器自己决定省略——**真人也是这么干的**。

## 4. 键盘的音色（自由弹奏配置）

**下层不一定是钢琴。** 旧实现的数据就是反例：

| 曲目 | 键盘下层 | 键盘上层 |
|---|---|---|
| Wish You Were Here | Acoustic Grand Piano | Synth Brass 2 |
| Another One Bites the Dust | **Rock Organ** | Synth Brass 1 |

规则：

- 自由弹奏时每层配置一个音色；MIDI 播放不受这个限制，多音色由独立播放器负责
- 同一层在**不同段落可以换音色**——这就是现场键盘手的"注册记忆"
- 所以**时间上错开的轨，在同一层上换音色即可**，不需要多摆琴

### 4.1 两层的音域不同 —— 这是硬约束

**实测两层的键数不一样**：

| 层 | 音域 | MIDI | 键数 |
|---|---|---|---|
| **下层** | **A0 – C8** | 21–108 | **88 键**（标准钢琴全键盘） |
| **上层** | **C2 – C7** | 36–96 | **61 键**（5 个八度） |

```
A0 ───────────────── C2 ══════════════ C7 ───────────── C8
      只有下层有键      ←  两层都有  →      只有下层有键
       (21–35)            (36–96)            (97–108)
```

**音符号落在某层音域外，那层根本没有这个键**——不是"弹错"，是弹不响。

所以分配**不是"低的给下层、高的给上层"这么简单**，分两步：

| 步骤 | 依据 |
|---|---|
| **① 先卡范围** | 音高 **< 36 或 > 96** 的轨 → **强制下层**（上层没这个键） |
| **② 再按音区** | 都落在 36–96 的 → 低的给下层、高的给上层 |

**分配影响**：超出上层音域的轨统一放下层，允许共享；不再因为两条轨都需要下层而新增键盘。超出整个模型音域的音符继续正常发声，但没有对应实体键可显示。

> 音色能力**已经放开**（见 4.2），两层的合成器完全对称，任何 0–127 的音色都能加载到任一层。
> 但**音色能换 ≠ 键够用**——这两件事要分开看。

### 4.2 音色能力（已实现）

```ts
keyboard.setProgram('lower' | 'upper', 0–127)   // 两层对称，无白名单
keyboard.program('lower' | 'upper')
keyboard.stepProgram(tier, ±1)
keyboard.status()                                // 只读状态快照
```

- **不需要音色白名单**——键盘是兜底乐器，128 个音色全都能加载
- 默认值仍是 `{ lower: 0, upper: 89 }`，所以现有行为零变化
- 电子琴近景左下角有一个**小面板**（两层各一个 128 项下拉 + 状态行），用来试听和验证

> **模型上的旋钮/推子/按钮目前仍是装饰**（每层约 21 个旋钮、13 个推子、8 个背光按钮、2 个屏幕，只有踏板设了 `userData.hit`）。用它们当音色入口是后续的事。

## 5. 排布

- **复用现有的自动排位器**（按每件占地宽度分行摆放，一行放不下换行）
- 同型号多件**必须有各自的声像（pan）**，左/中/右分开——否则同音色叠在一起听起来还是一把
- **加一条"不能越过 LED 净空线"的兜底**：旧实现是 `MAIN_LED_Z (-8.17) + 0.95`，越线就往前推

## 6. 播放

```
音频时钟为主
每一帧：
   把已到时间的音符推给 [乐器][层] 的 noteOn
   把已到时间的结束推 noteOff
   调每件乐器的 update(dt) 让它们动
```

必须处理的几件事（旧实现都有做法可照）：

| | 做法 |
|---|---|
| **提前量** | 音符 `+6ms`、鼓 `+10ms` —— 视觉略早于声音 |
| **多队列游标** | 按下 / 松开 / 鼓 / 踏板**各一条有序队列、各一个游标**，不是每帧全扫 |
| **时值封顶** | 按角色限长：下层 5.5s、上层 4.0s、贝斯 3.0s、电吉他 4.2s、其他 2.8s。**防止长音把乐器一直按住** |
| **拖动进度** | 时间跳变 > 0.45s 时**重建状态**：全部清空 → 重新按下"此刻正响"的音 → 踏板状态按时间点还原 → 弦乐只重触发正在响的音、**限流最后 12 个** |
| **暂停 / 停止** | 全部松开 + panic（含延音踏板复位） |
| **音符分配固化** | 每个音符归哪件乐器、哪一层，**解析时就定好写进数据**，运行时不现算 |

### 10.2 实现中撞到的四个坑

**① "这一轨在响"不能按音符算**
一条连续的断奏钢琴轨，音符之间都是缝，按"此刻有没有音符在发声"去数，它会一闪一闪，**同时发声数被严重少算**（实测峰值从 5 被算成 4）。正确模型是"**这一段他是否在演奏**"——间隔小于 1 秒的当连续。

**② 分配要"最受限优先"**
以下为旧版分配实验记录，键盘扩容规则已被第 3 节的单台合并策略替代。

钢琴音域 G1–D6 **超出上层键盘的下限 C2**，所以它只能在下层。如果先到的是音域不受限的合唱轨，它会占掉下层，**逼出一台多余的键盘**。改成受限的先挑，3 台变 2 台。

**③ 不能用"时钟跳变"来判断 seek**
原来 `update()` 里有个 `now - lastTime > 0.45s 就当 seek` 的保护。但**慢机器上一帧就超过 0.45 秒**，于是每帧都被判成 seek → 每帧重建整个乐队 → **乐器永远动不起来**。seek 只由显式调用处理，挂起交给 `visibilitychange`。

**④ 重建状态时 on/off 必须按时间交错**
`repress()` 里"先把所有 note-on 扫一遍、再把所有 note-off 扫一遍"看着等价，其实不是：**100 秒松开的那个音，会把 199 秒重新按下的同一个音删掉**。结果 seek 之后整个乐队是哑的。必须合并成一条按时间排序的扫描。

### 10.3 实测（Bohemian Rhapsody，27 条轨 / 15 条有声）

```
鼓×1  贝斯×1  键盘×3  电吉他×3      共 8 件
```

- 键盘 3 台：钢琴（下层）+ 合唱（上层）、萨克斯 + 合唱、合唱×2 —— 3:22–4:00 有 **6 个声部同时**

播放验证：seek 到 225 秒时，**三台键盘上分别有 35 / 23 / 8 个键被按住**。

### 10.4 已知的边界

- **近景机位没有做多实例**：机位 id 里写死了 `violin.main:whole`，两把提琴会撞 id。演奏模式只用舞台机位，所以不受影响；但**要支持"走进第二把提琴"就得把机位 id 按实例命名**。
- 播放期间切到后台再回来会重建状态，**正在响的音会重新触发一次**。
- 没有做"提前量补偿到音频时间"——音符是按帧触发的，帧率低时会在 10ms 量级上抖。
