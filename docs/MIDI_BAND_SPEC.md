# MIDI 驱动虚拟乐队 · 规格

**目标**：任意一个 MIDI 文件丢进来，自动分配出一支虚拟乐队，让它们按谱演奏。

**原则**：尽可能符合现实——现实中一个岗位一个人，缺的声部由键盘手补。

**状态**：规格已定，**MIDI 驱动本身尚未实现**。

各乐器的**音色接入已经做完**（见 7.1），剩余的"调音色"工作见第 8 节。第 4 节的键盘部分已实现并验证。

---

## 1. 总流程

```
任意 MIDI
   │
   ├─ ① 逐条轨：取主音色（出现最多的 program）+ 通道
   │
   ├─ ② 按归并表 → 6 类乐器之一
   │
   ├─ ③ 每一类算"同一时刻最多几个声部" → 定件数
   │
   ├─ ④ 自动排布到舞台
   │
   └─ ⑤ 播放：按时间把音符推给对应乐器的对应层
```

**没有手写表，没有按曲子的特殊处理。** 同一套规则吃所有 MIDI。

## 2. 归并表

按 GM 音色号（General MIDI program）归并到 6 类乐器。

| GM | 家族 | 归到 | 依据 |
|---|---|---|---|
| 1–8 | 钢琴 | **键盘** | 真实 |
| 9–16 | 色彩打击 | **键盘** | 键盘手打 |
| 17–24 | 风琴 | **键盘** | 真实 |
| 25 | 尼龙弦吉他 | **木吉他** | 真实 |
| 26–32 | 电吉他类 | **电吉他** | 真实 |
| 33–38 | 贝斯 | **贝斯** | 真实 |
| **39–40** | **合成贝斯** | **键盘** | 合成 |
| 41–44 | 弦乐（小提琴/中提琴/大提琴/低音提琴） | **提琴** | 真实 |
| **45** | **Tremolo Strings 震音** | **键盘** | ⚠️ 提琴接不了，见 2.2 |
| **46** | **Pizzicato Strings 拨弦** | **提琴** | 演奏技法，切拨弦方式 |
| **47** | **Orchestral Harp 竖琴** | **键盘** | ⚠️ GM 归错家族 |
| **48** | **Timpani 定音鼓** | **键盘** | ⚠️ GM 归错家族 + **鼓接不了**，见 2.2 |
| **49–50** | **弦乐合奏 1/2** | **键盘** | ⚠️ 提琴接不了，见 2.2 |
| **51–52** | **合成弦乐** | **键盘** | 合成 |
| 53–56 | 合唱 / 人声 / 管弦乐 Hit | **键盘** | 无对应乐手 |
| 57–64 | 铜管 | **键盘** | 现场键盘补 |
| 65–72 | 簧管 | **键盘** | 现场键盘补 |
| 73–80 | 管乐 | **键盘** | 现场键盘补 |
| 81–88 | **合成主音** | **键盘** | 合成 |
| 89–96 | 合成铺底 | **键盘** | 合成 |
| 97–104 | 合成效果 | **键盘** | 合成 |
| **105–112** | **民族拨弦** | **键盘** | ⚠️ 木吉他接不了，见 2.2 |
| **113–120** | **打击（旋律通道）** | **键盘** | ⚠️ 鼓接不了，见 2.2 |
| 121–128 | 音效 | **键盘** | — |
| **通道 10** | — | **鼓** | 不看音色 |

**一句话原则**：有对应实体乐手**而且那件乐器真能加载这个音色**的，给他；其余全给键盘。

> **注意"合成"这个词**：合成贝斯（39–40）、合成弦乐（51–52）、合成主音（81–88）、合成铺底（89–96）、合成效果（97–104）**都归键盘**，不归对应家族的实体乐器。现实中这些音色本来就是键盘手弹的。

**判定方式**：每条轨取它的**主音色**（该轨出现最多的 program）定归属，**不是逐音符判**。

### 2.1 GM 的家族划分有例外，不能纯按家族走

**GM 的家族是功能上的近似，不是严格按乐器学。** 最明显的是"弦乐"家族（41–48）里塞了两件不是弦乐的乐器：

| GM | 名称 | GM 放在 | 实际是 | 改成 |
|---|---|---|---|---|
| **47** | Orchestral Harp | 弦乐 | **竖琴**（拨弦，不是弓弦） | **键盘** |
| **48** | Timpani | 弦乐 | **定音鼓（打击乐！）** | **键盘**（见 2.2） |

**不修的话**：一条定音鼓的轨会被归到提琴，变成"台上一把小提琴在敲定音鼓"——声音和画面都不对。

还有两个是**演奏技法**而不是另一件乐器，不能当普通音色处理：

| GM | 名称 | 怎么处理 |
|---|---|---|
| **45** | Tremolo Strings | 定弦同小提琴，但**提琴表里没有这个音色** → 先归**键盘**（见 2.2） |
| **46** | Pizzicato Strings | 提琴 + **切"拨弦"演奏方式**（按 `2`），不是换音色 |

> **尚未逐个核对完 128 个音色。** 目前只把"弦乐"这一家族逐个过了一遍（因为要先接提琴）。其余家族可能还有放错位置的，**归并实现之前应该把 128 个全过一遍**。

### 2.2 落不到实体乐器的，一律先给键盘

**原则：先保证出声。** 表里标 ⚠️ 的音色，归并表本来想给某件实体乐器，但**那件乐器现在加载不了它们**：

| 音色 | 本来的归属 | 为什么给不了 |
|---|---|---|
| **45** Tremolo Strings | 提琴 | 提琴的音色表只有 40–43 |
| **48** Timpani | 鼓 | 鼓的后端写死 `bank 128`（鼓组），**加载不了旋律音色** |
| **49–50** 弦乐合奏 1/2 | 提琴 | 同上，表里没有这两个 |
| **105–112** 民族拨弦（8 个） | 木吉他 | 木吉他的表只有 24–25 |
| **113–120** 打击·旋律通道（8 个） | 鼓 | 同 48，鼓加载不了旋律音色 |

**共 20 个音色，全部改成归键盘**——键盘是唯一能加载任意 GM 音色的乐器（128 个全能），所以这 20 个**立刻就能出声**，**不需要改任何代码**。

**这也是符合现实的**：键盘手补弦乐垫、补定音鼓、补西塔琴班卓，本来就是现场常见做法。

> **以后想更准，可以逐个补**（都不难，但都要动代码）：
> - **提琴**加 `44 / 48 / 49` 到音色表 —— **一行改动**，而且弦乐合奏给提琴比给键盘更像样
> - **木吉他**加 `104–111` —— 但里面 **Bagpipe 风笛**、**Kalimba 卡林巴**、**Fiddle 小提琴** 三件不是拨弦木吉他，**归键盘反而更对**
> - **鼓**加"能加载 bank 0 旋律音色"的能力 —— 中等改动，只为 `112–120` 这 9 个

**先按全归键盘走，上面的优化留作以后。**

## 3. 件数规则

| 乐器 | 件数 | 理由 |
|---|---|---|
| **鼓** | **恒 1** | 一套鼓天生多声部（底鼓/军鼓/嗵鼓/镲同时响很正常），不存在"演不出来"；现实中不会两个鼓手共用一套鼓。多条鼓轨并到一套上 |
| **贝斯** | **恒 1** | 合成贝斯（39–40）已分给键盘，剩下归贝斯的都是真实贝斯音色，现实中就是 1 把 |
| **键盘** | **算** | 一台琴 = 两层 = 同时最多容纳 2 个声部 |
| **电吉他 / 木吉他 / 提琴** | **算** | 按"同一时刻最多几条轨在响" |

### 3.1 "同一时刻最多多少"怎么算

```
① 归类完成后，把该类的所有轨的音符合并
② 每个音符产生两个事件：开始(+1)、结束(−1)
③ 按时间排序，扫一遍
④ 记录"此刻有几条轨正在响"的峰值
⑤ 只看持续 > 1 秒的重叠（短于一秒的叠音听不出来，不算）
```

判定：

| 同时声部 | 持续时长 | 结果 |
|---|---|---|
| ≤ 2 | — | **1 件** |
| 3–4 | < 1 秒 | **1 件**（挤一下，次要的略过） |
| 3–4 | > 1 秒 | **2 件** |
| 5+ | > 1 秒 | 继续加 |

**键盘**：同时 ≤ 2 → 1 台；3–4 → 2 台；依此类推。

> 这个数**可以在解析时算出来并打印**，例如：
> `键盘：轨道 6 条，同时最多 3 条（1:23–1:27，持续 4.1 秒）→ 2 台`
> **默认自动，但结论看得见、可以覆盖。**

### 3.2 一件乐器自身能演几个音

超出时不是立刻加件，**先让这件乐器自己吸收**（它天生多声部）：

| 乐器 | 同时最多 |
|---|---|
| 键盘 | 10（十指，常用 6–8） |
| 电吉他 / 木吉他 | 6（六根弦） |
| 贝斯 / 提琴 | 4（四弦） |

接不下的音由乐器自己决定省略——**真人也是这么干的**。

## 4. 键盘的音色 ★待调

**下层不一定是钢琴。** 旧实现的数据就是反例：

| 曲目 | 键盘下层 | 键盘上层 |
|---|---|---|
| Wish You Were Here | Acoustic Grand Piano | Synth Brass 2 |
| Another One Bites the Dust | **Rock Organ** | Synth Brass 1 |

规则：

- 一台琴两层，**每层配一个音色**，用**原曲的真实音色**
- 同一层在**不同段落可以换音色**——这就是现场键盘手的"注册记忆"
- 所以**时间上错开的轨，在同一层上换音色即可**，不需要多摆琴

### 4.1 两层的音域不同 —— 这是硬约束

**实测两层的键数不一样**：

| 层 | 音域 | MIDI | 键数 |
|---|---|---|---|
| **下层** | **A0 – C8** | 21–108 | **88 键**（标准钢琴全键盘） |
| **上层** | **C2 – C7** | 36–96 | **61 键**（5 个八度） |

```
A0 ───────────────── C2 ══════════════ C7 ───────────── C8
      只有下层有键      ←  两层都有  →      只有下层有键
       (21–35)            (36–96)            (97–108)
```

**音符号落在某层音域外，那层根本没有这个键**——不是"弹错"，是弹不响。

所以分配**不是"低的给下层、高的给上层"这么简单**，分两步：

| 步骤 | 依据 |
|---|---|
| **① 先卡范围** | 音高 **< 36 或 > 96** 的轨 → **强制下层**（上层没这个键） |
| **② 再按音区** | 都落在 36–96 的 → 低的给下层、高的给上层 |

**连带影响**：一条轨如果因为音域被强制到下层，下层就被占住了；第二条同时在响的轨**只能去上层**（前提是它落在 C2–C7 里）。**如果两条都必须在下层，就只能加第二台琴。**

> 音色能力**已经放开**（见 4.2），两层的合成器完全对称，任何 0–127 的音色都能加载到任一层。
> 但**音色能换 ≠ 键够用**——这两件事要分开看。

### 4.2 音色能力（已实现）

```ts
keyboard.setProgram('lower' | 'upper', 0–127)   // 两层对称，无白名单
keyboard.program('lower' | 'upper')
keyboard.stepProgram(tier, ±1)
keyboard.status()                                // 只读状态快照
```

- **不需要音色白名单**——键盘是兜底乐器，128 个音色全都能加载
- 默认值仍是 `{ lower: 0, upper: 89 }`，所以现有行为零变化
- 电子琴近景左下角有一个**小面板**（两层各一个 128 项下拉 + 状态行），用来试听和验证

> **模型上的旋钮/推子/按钮目前仍是装饰**（每层约 21 个旋钮、13 个推子、8 个背光按钮、2 个屏幕，只有踏板设了 `userData.hit`）。用它们当音色入口是后续的事。

## 5. 排布

- **复用现有的自动排位器**（按每件占地宽度分行摆放，一行放不下换行）
- 同型号多件**必须有各自的声像（pan）**，左/中/右分开——否则同音色叠在一起听起来还是一把
- **加一条"不能越过 LED 净空线"的兜底**：旧实现是 `MAIN_LED_Z (-8.17) + 0.95`，越线就往前推

## 6. 播放

```
音频时钟为主
每一帧：
   把已到时间的音符推给 [乐器][层] 的 noteOn
   把已到时间的结束推 noteOff
   调每件乐器的 update(dt) 让它们动
```

必须处理的几件事（旧实现都有做法可照）：

| | 做法 |
|---|---|
| **提前量** | 音符 `+6ms`、鼓 `+10ms` —— 视觉略早于声音 |
| **多队列游标** | 按下 / 松开 / 鼓 / 踏板**各一条有序队列、各一个游标**，不是每帧全扫 |
| **时值封顶** | 按角色限长：下层 5.5s、上层 4.0s、贝斯 3.0s、电吉他 4.2s、其他 2.8s。**防止长音把乐器一直按住** |
| **拖动进度** | 时间跳变 > 0.45s 时**重建状态**：全部清空 → 重新按下"此刻正响"的音 → 踏板状态按时间点还原 → 弦乐只重触发正在响的音、**限流最后 12 个** |
| **暂停 / 停止** | 全部松开 + panic（含延音踏板复位） |
| **音符分配固化** | 每个音符归哪件乐器、哪一层，**解析时就定好写进数据**，运行时不现算 |

## 9. 参考：旧实现（分支 `nocturne-integrated-fix`）

旧实现做过同样的事，**做法可照，但不要照搬它的编制**。

| 文件 | 内容 |
|---|---|
| `src/data/song-library-loader.js` | 读 `assets/songs/*.json.gz`（wish / hey / africa / dust / children） |
| `src/runtime/app.js` | 音符调度、`visualOn/Off` 分发、跳转恢复、时值封顶 |
| `src/venues/nocturne-band-layout.js` | 多件乐器的位置表 + **LED 净空保护** |

**旧的数据格式**（`assets/songs/*.json.gz`）：

```
顶层：artist, title, bpm, duration, subtitle, cards, stage, events, pedals, tones
事件：{ s:开始, e:结束, ve, i:角色, x:lane(第几件/第几层), n:音高, v:力度, pg:音色号, tone:音色id, id }
tones：{ 音色id: { instrument:'GM音色名', pan:声像, volume:音量 } }
```

**关键**：`i`（角色）+ `x`（lane）**就是本文档说的"哪件乐器、哪一层"**，在烘焙时就固化好了。

> **旧实现的编制不要照搬**：它给 Wish You Were Here 排了 3 把木吉他 + 3 把电吉他，
> 那是**录音室叠录层数**，不是现场编制，台上一眼看过去不像乐队。
> 本文档第 3 节的件数规则就是为了避免这个。

**旧实现没有的东西**：烘焙脚本（`.mid` → `*.json.gz`）**仓库里从来没有过**，只有产物。
所以这套流程要从头写。
