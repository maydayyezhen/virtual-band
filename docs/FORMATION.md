# 自动编队

`/studio/band/` 与 `/studio/layout/` 使用同一条编队链。舞台坐标以米为单位，+Z 朝观众；场馆提供空间约束，乐器提供占位描述，编队提供位置，场景适配层应用结果。

## 模块边界

- `Formation.ts`：纯数据队形和碰撞求解。输入实例 ID、旋转后的宽深、站位偏好、原位置、锁定状态，以及显式 `StageLayout`。不导入 Three.js、乐器目录、NOCTURNE、MIDI、灯光或镜头。
- `LayoutDocument.ts`：当前支持的乐器定义提供 `space`、真实高度、默认朝向及 `placement`（`rear-center` / `wing` / `front`）。保存文档仍为 schema 3；新增站位偏好不是实例 JSON 的必填字段。
- `AutoLayout.ts`：文档与实测尺寸的适配层。使用模型占位和演奏空间的较大值，应用实例比例及 Y 轴旋转，转换为核心输入。场馆必须由调用方传入，不存在隐藏的默认 NOCTURNE。
- `BandSession`：准备并验证完整的新布局，复用已有模型对象。`presentBand` 按 ID 应用绝对变换。镜头继续读取摆放后的乐队范围进行取景。

## 队形与约束

先按整个编制生成目标队形，再放入锁定对象并调整冲突。后排中心用于鼓组等视觉锚点；侧翼从中心两边向外展开，多件侧翼乐器形成两侧分组，不默认塞到鼓后面。前排横向展开为浅弧，队形宽度由人数、占位和后排宽度共同决定。

`CONCERT_FORMATION` 集中声明构图间距、行距、前排展开宽度与弧度。场馆 `gap` 则表示不可突破的安全间距。没有根据舞台大小自动缩放乐器，也没有使用显示屏或灯光尺寸作为乐器尺寸。

求解时按角色、占地面积、稳定实例 ID 排序。首选位置合法便直接使用；冲突时搜索舞台内的有限网格，移动纵深的代价高于横向移动，以保留前后层次。搜索每轴最多 97 个点。锁定位置、禁区、边界和占位间距是硬约束，构图位置是偏好。

失败返回 `issues` / `unplaced`，文档适配层不提交部分排位。该算法没有全局回溯，不保证任何有数学解的装箱都能找到；空间不足或锁定过多时需要修改编制、锁定位置或场馆。

## 换曲与手动布局

自动位置随整个编制重排，不把所有旧实例当作固定障碍。相同编制、尺寸、旋转、比例、锁定信息和场馆得到相同结果，输出不依赖数组顺序或未锁定的历史位置。用户要让位置跨歌曲保持不变，应在编辑器锁定该实例。

载入 JSON 时先调用独立 `validateLayout` 校验并精确应用保存的变换，不重排。后续用户点击“重新排位”或载入 MIDI 时，未锁定的位置再次参与编队。保存文件的 `venueId` 在克隆和序列化中保持；当前场馆不接受其他场馆的布局，旧 `atelier-studio` 文件仍按原有迁移规则转换。

## 新乐器与新场馆

新增乐器类型时，在乐器描述中声明演奏空间和站位偏好；模型与音频实现仍由各自模块提供。编队核心的输入不包含类型名称，例如马林巴可以提供 `{ id, width, depth, role: 'wing', position, locked }`，无需在算法里添加分支。

新场馆提供 `StageLayout`，包括局部可用矩形、禁放矩形、舞台高度和最小间距。此版只支持平坦舞台上的矩形约束；异形边界、多层升降台和正面投影遮挡优化需要另行扩展。

验证：`npm run layout:verify`、`npm run formation:browser`、`npm run stage:browser`、`npm run camera:browser` 与 `npm run build`。浏览器验证使用 Chrome；截图可通过 `SCREENSHOT_DIR` 保存。
